# 05 · 模型是怎么训出来的

## 一句话总结

三个阶段：**预训练**（读遍互联网，学会"接着写"）→ **微调 SFT**（学会"按指令回答"）→ **对齐 RLHF/DPO**（学会"说得让人喜欢、少说危险的话"）。

## 核心概念

### 阶段一：预训练（最贵，占 95% 以上算力）

- 数据：网页、书籍、代码、论文，几万亿 token
- 目标：就是第一篇说的"预测下一个 token"
- 产物：**基座模型（base model）**。它不会回答问题，只会续写。你问它"法国的首都是？"，它可能续写成一串类似的问答对，而不是"巴黎"

**关键理解**：知识、语法、推理能力，全是在这一步"压"进权重的。后面的阶段是在**调教表达方式**，不是灌知识。

### 阶段二：SFT（监督微调）

用几万到几百万条「指令 → 优质回答」的样本，继续训练。模型学会：
- 看到问题要回答，而不是续写
- 按格式输出（列表、JSON、代码块）
- 扮演指定角色

这解释了为什么**提示词有效**：模型被训练成"看到这种模式就那样回答"。

### 阶段三：对齐（RLHF / DPO）

人类给多个回答排序，训练一个"打分器"（reward model），再用强化学习让模型输出得分更高的回答。效果：

| 变好 | 变差（副作用） |
|---|---|
| 更礼貌、更结构化 | 更保守，过度拒绝 |
| 更少胡说八道（部分） | 更爱"安全地正确"，答案变平庸 |
| 更愿意拒答危险请求 | 有时拒绝正常请求（false refusal） |

**实用推论**：如果你觉得模型"太端着""不敢下判断"，可以在提示词里明确解除这种倾向（`直接给结论，不需要免责声明`），这是对齐副作用，不是能力问题。

### 补充：蒸馏与量化

- **蒸馏**：大模型生成数据，训小模型 → 小模型学到部分能力，便宜很多
- **量化**：权重从 16 位压到 8/4 位 → 省显存，略掉精度

### Scaling Law 的一句话版

在数据、参数、算力同步增长时，损失随规模呈幂律下降——**可预测地变好**。这也是这几年大家敢砸钱的原因。但"能力提升"不等于"可靠性提升"，这是两回事。

## 动手实验

### 实验 1：感受对齐的痕迹

同一个问题问三遍，每次换一种"人设"：
1. `你是严谨的审核员，指出这段文案的问题`
2. `你是这文案的作者，替它辩护`
3. `不要客套，直接说最刺耳的问题`

**观察**：同一个模型，语气和立场完全不同 → 说明对齐层是"可被提示词覆盖的软约束"。

### 实验 2：基座 vs 对话

如果你能用上 base 模型（很多平台提供），问它"1+1 等于几"。
**观察**：base 模型可能续写成"1+1 等于几？1+1 等于 2。"—— 它把你的问题当成文档的一部分在续写。这就是 SFT 前后最直观的差别。

### 实验 3：过度拒绝

找几个完全正常但带敏感词的请求（比如"如何安全地处理厨房刀具"），看模型是否拒答。记录 3 个例子。
