# 07 · 幻觉与能力边界

## 一句话总结

幻觉是"预测下一个 token"这个机制的必然产物：模型优化的是**像不像话**，不是**对不对**。所以它错的时候，语气和它对的时候一模一样。

## 核心概念

### 1. 幻觉的三种成因

| 类型 | 例子 | 机制 |
|---|---|---|
| **知识缺失** | 编造不存在的论文、法条、API | 上下文里没有 → 用"最像话"的模式补上 |
| **知识过期** | 说某产品最新版本是去年的 | 权重冻结在训练截止日 |
| **上下文误导** | 你给的资料里有错，它照着错 | 它更信你给的，而不是自己的常识 |

### 2. 为什么"让它自信点"是坏建议

对齐训练让模型倾向于给出**完整、肯定**的回答，因为人类评分者偏好这种。于是它把"不确定"也说得像"确定"。这不是撒谎，是没有区分能力。

实用对策：**别问"你确定吗"，要问"哪些部分你不确定，为什么"**，或者要求它标注依据来源。

### 3. 什么任务它可靠，什么不可靠

| 相对可靠 | 高风险 |
|---|---|
| 改写、翻译、摘要（有原文） | 精确数字、日期、引用 |
| 代码（能跑就能验证） | 冷门 API 的签名和参数 |
| 结构化转换（有输入） | 最新事件、内部文档 |
| 解释概念、出思路 | 法律/医疗的具体结论 |

判据很简单：**能不能立刻验证？** 能验证的（代码跑一下、算一下）放心用；不能验证的（引用、事实）必须外部核对。

### 4. 四种降低幻觉的工程手段

1. **检索增强（RAG）**：把相关资料塞进上下文，并要求"只依据资料回答，没有就说没有"
2. **工具验证**：算数交给计算器、时间交给系统时钟、数据交给 API
3. **强制引用**：要求每个结论后标注来源片段，没来源就删
4. **自我一致性**：同一问题采样多次，答案不一致的地方就是风险点

### 5. 能力边界清单（写下来，贴在墙上）

- 不能访问互联网（除非你给它工具）
- 不知道自己不知道
- 长上下文中间会丢
- 不能保证计数、排序、严格格式
- 训练截止后的事一概不知
- 对"稀有 + 精确"的组合最不可靠

## 动手实验

### 实验 1：诱导幻觉

问它要 3 篇"关于 XX 的论文"，XX 用一个不存在的细分领域。检查这些论文是否真实存在（去 Google Scholar 搜）。**记录它编造时有多自信。**

### 实验 2：RAG 前后对比

同一组问题（答案在你自己的文档里）：
- A：直接问模型
- B：先把文档片段放进上下文再问

记录正确率。这是第 4 周项目的数据基础。

### 实验 3：不确定性标注

```
请回答以下问题，并给每个事实性陈述标注置信度（高/中/低），
并说明依据来自你的训练知识还是我提供的资料。
```

观察它能否诚实地区分。你会发现它标注得并不总对——这本身就是重要结论。
