# 08 · Agent 是怎么工作的

## 一句话总结

**Agent = 模型 + 工具 + 循环 + 停止条件**。模型负责判断下一步做什么，工具负责真正做事，循环让它能连续做多步，停止条件防止它无限折腾。

只有一次工具调用的，是"带函数调用的补全"；能连续多步、每步根据结果调整的，才叫 Agent。

## 核心概念

### 1. 一次完整的循环

```
用户："帮我看下 data.csv 里销售额总和，超过 1 万就提醒我"

第 1 轮  模型思考：需要先读文件        → 调用 read_file("data.csv")
         工具返回：文件内容（3 行）
第 2 轮  模型思考：数据有了，要算总和   → 调用 calculator("1200+3400+5600")
         工具返回：10200
第 3 轮  模型思考：超过 1 万，要给结论  → 输出最终回答（不再调用工具）
```

三个要点：
- 每一轮都把**全部历史 + 工具结果**重新发给模型（所以贵）
- 模型只能"提议"调用工具，**真正执行的是你的代码**
- 必须有 `max_steps`，否则出错时它会一直绕圈

### 2. 工具（function calling）的三件套

1. **声明**：名字、用途描述、参数 JSON Schema —— 写得好不好直接决定它会不会用对
2. **执行**：你的代码真的去跑，捕获异常，把错误信息原样回给模型
3. **结果格式化**：返回结构要稳定、别太长（几千字的工具输出会挤爆上下文）

> 工具描述比工具实现更重要。写 `查询天气` 不如写 `get_weather(city: 城市中文名, date: YYYY-MM-DD)，返回当日最高/最低温与降水概率，仅支持中国城市`。

### 3. ReAct：让思考和行动交替出现

```
Thought: 我需要知道今天的日期才能算"这周"
Action: get_current_time()
Observation: 2026-11-05 星期四
Thought: 本周一是 11-03，需要读取消费记录
Action: read_file("expenses.csv")
...
Answer: 本周共花费 486 元，其中餐饮 312 元
```

显式写 `Thought` 的价值：把推理过程变成上下文的一部分，后面每一步都能"看见"自己之前的判断，减少前后矛盾。

### 4. 记忆的三层

| 层 | 存哪 | 装什么 | 会怎样丢 |
|---|---|---|---|
| 工作记忆 | 当前上下文 | 本任务的步骤、中间结果 | 超长被截断 |
| 短期记忆 | 会话历史（可能压缩成摘要） | 之前聊过什么 | 摘要丢细节 |
| 长期记忆 | 外部存储（文件/向量库/数据库） | 用户偏好、历史经验 | 检索不到就等于没有 |

关键认识：**模型本身没有记忆**，所有"记住"都是你把它重新塞进上下文。

### 5. 规划：两种风格

- **先规划后执行**（plan-and-execute）：先列出 5 步，再逐步做。优点是可检查、可中断；缺点是计划错了会一路错下去
- **边走边看**（react）：每步根据反馈决定下一步。优点是灵活；缺点是容易跑偏、成本高

实践建议：**中等复杂任务用"先列计划 → 人工确认 → 执行"**，简单任务直接 ReAct。

### 6. 六个常见翻车方式

| 翻车 | 表现 | 防护 |
|---|---|---|
| 无限循环 | 反复调同一个工具 | `max_steps` + 检测重复调用 |
| 幻觉工具 | 调用不存在的工具/参数 | 严格 schema 校验，失败回传错误 |
| 上下文炸裂 | 工具返回巨量文本 | 截断 + 摘要 + 分页 |
| 目标漂移 | 做到第 5 步忘了原始任务 | 每轮把原始目标重述一遍 |
| 危险操作 | 删文件、发邮件、付款 | 白名单 + 人工确认 + 只读默认 |
| 静默失败 | 工具报错被吞掉，模型继续编 | 错误必须显式回传给模型 |

## 动手实验

### 实验 1：最小 Agent（不用框架）

用 30 行代码写一个只有 2 个工具（当前时间、加法）的循环，`print` 每一轮的 thought/action/observation。
**这是第 5 周项目的骨架，先手写一遍，别用 LangChain。**

### 实验 2：工具描述实验

同一个工具，写两种描述（模糊版 vs 精确版），跑 10 个任务，统计调用成功率。差值就是"提示词工程在 Agent 里的分量"。

### 实验 3：逼它翻车

- 让它调一个不存在的文件 → 看它怎么处理错误
- 让工具返回 5000 字垃圾 → 看上下文怎么被吃掉
- 把 `max_steps` 设成 2 → 看它半路停下的表现
