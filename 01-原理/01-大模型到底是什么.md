# 01 · 大模型到底是什么

## 一句话总结

模型不"知道"任何事实，它只是在**给定前文的情况下，算出下一个 token 的概率分布**，然后抽一个。

## 核心概念

### 1. 一个被反复念叨但很少被真正理解的例子

输入：`今天天气真`

模型输出的不是一个词，而是一整张概率表：

| 候选 | 概率 |
|---|---|
| 好 | 0.62 |
| 不错 | 0.14 |
| 热 | 0.09 |
| 冷 | 0.06 |
| 适合 | 0.03 |
| …（词表里还有十万个） | … |

然后按这张表**抽签**，抽到"好"，句子变成"今天天气真好"，再把整句喂回去，猜下一个。这叫**自回归生成**。

推论：
- 同一句话问两次，答案可能不同 → 因为抽签（第 6 篇会讲怎么控制）
- 它没有"回头改"的能力 → 一旦写上就沿着这条概率路径走下去，这就是"越写越偏"
- 它不知道自己在编 → 编出来的内容同样是一条高概率的续写路径

### 2. 那为什么它能做数学、写代码？

因为"接着写"这个任务，在海量数据上逼出了中间能力：
- 看到 `def fib(n):` 的代码上下文，最高概率的续写是能跑的代码，不是随便的字符
- 看到 `13 × 17 =`，训练数据里这类式子后面跟着 `221` 的次数足够多
- 写推理步骤（`先算…再算…`）时，后面的答案概率会被前面步骤"锚定"，所以**让它一步步写，正确率会上升**——这其实就是思维链（CoT）为什么有效的朴素解释

一句话：**推理能力是"预测下一个 token"这个目标在足够大的数据和模型上涌现出来的副产物**，不是被专门设计的。

### 3. 参数是什么

模型内部是几十亿到上万亿个数字（权重）。这些数字唯一的作用是：把输入的 token 序列，变成下一个 token 的概率分布。训练 = 调整这些数字，让它在训练数据上的"猜中率"更高。

所以模型没有数据库，只有**被压缩进权重里的统计规律**。这解释了两件事：
- 常识它很行（规律见得多）
- 精确事实它不可靠（要精确记住一串数字，代价高，而且会被"最像话"的规律带偏）

## 动手实验

### 实验 1：看它怎么补全

```python
from openai import OpenAI
client = OpenAI()

prompt = "今天天气真"
for i in range(5):
    r = client.chat.completions.create(
        model="deepseek-chat",
        messages=[{"role": "user", "content": prompt}],
        max_tokens=5,
        temperature=1.3,
    )
    print(i, r.choices[0].message.content)
```

**观察**：同一个开头，5 次结果不一样；把 `temperature` 改成 0，5 次就几乎一样了。

### 实验 2：让它"猜"而不是"查"

问三个问题，记录它答得对不对：
1. 圆周率第 50 位是多少？
2. 昨天你所在城市下雨了吗？
3. 一个 2019 年才成立的公司的创始人是谁？

**观察**：凡是需要"精确记忆某条罕见信息"的，它就容易编。编的时候语气和答对时一模一样——这就是下一条要记住的事。

### 实验 3：思维链的朴素验证

同一个数学题问两遍：

- 甲：`23 × 47 等于多少？直接给数字。`
- 乙：`23 × 47 等于多少？先分解成 23×40 和 23×7 再相加。`

对比正确率（多试几道）。你会看到"让它写中间步骤"的效果。
