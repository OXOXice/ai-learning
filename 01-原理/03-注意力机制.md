# 03 · 注意力机制

## 一句话总结

处理某个词时，模型让这个词去**问其他所有词**"你和我有关系吗"，按相关度加权吸收它们的信息。这就是全部。

## 核心概念

### 1. 一个不需要数学的直觉

读这句话：`小明把苹果给了小红，因为她饿了。`

"她"指谁？你的大脑会自动回头看"小明""苹果""小红"，给"小红"最高权重。**注意力就是把这个动作变成矩阵运算**。

### 2. Q、K、V：三个角色

每个 token 的向量会被投影成三个新向量：

| 角色 | 含义 | 类比 |
|---|---|---|
| Q（Query） | 我在找什么 | 你输入的搜索词 |
| K（Key） | 我有什么标签 | 每篇文章的标题 |
| V（Value） | 我实际提供的内容 | 文章正文 |

计算三步：

```
1. 打分：score = Q · K        （我的问题和你的标签有多match）
2. 归一：weights = softmax(score / √d)   （变成加起来等于 1 的权重）
3. 聚合：output = Σ weights × V          （按权重把内容混起来）
```

除以 `√d` 是防止维度高时点积过大、softmax 变成"全押一个"。

### 3. 手算一个例子

三个 token，维度 2，假设已经算好打分：

| | 对 A | 对 B | 对 C |
|---|---|---|---|
| 当前 token 的关注分 | 2.0 | 1.0 | 0.0 |

softmax（先除以 √2 简化起见直接用原值）：`e^2=7.39, e^1=2.72, e^0=1`
总和 = 11.11 → 权重 = **(0.665, 0.245, 0.090)**

如果 V 分别是 (1,0)、(0,1)、(1,1)，那么输出：
`0.665×(1,0) + 0.245×(0,1) + 0.090×(1,1) = (0.755, 0.335)`

**这就是"主要看 A、少量看 B"的数学表达。**

### 4. 多头：同时问不同的问题

一个头可能学"指代关系"，另一个头学"语法主谓"，还有一个学"上一句的主题"。多头就是并行做十几次上面那套，再把结果拼起来。

### 5. 三个必须知道的推论

1. **因果掩码**：生成时，每个 token 只能看它前面的（不能偷看未来），这就是为什么"下一个字"任务能成立
2. **O(n²) 成本**：n 个 token 两两都要打分，长度翻倍成本翻四倍 → 长上下文很贵
3. **位置信息要额外注入**：注意力本身不含顺序，所以有位置编码；这也是"模型偶尔搞混顺序"的根源

## 动手实验

### 实验 1：可视化注意力

用 Transformer 可视化工具（如 BertViz / `exBERT`），输入 `The animal didn't cross the street because it was too tired`，看 `it` 的注意力落在 `animal` 上。换成 `because it was too wide`，看落到 `street` 上。

**这一步比读十篇博客都值。**

### 实验 2：让模型暴露它的"回头看"

```
输入：把下面这句话拆成主语/谓语/宾语，并说明"它"指的是谁：
"老王把书递给了小李，因为他要还书。"
```

多试几个指代模糊的句子。你会发现模型大部分时候对，但一旦句子长、指代远，就开始猜。这正是注意力权重被稀释的表现。

### 实验 3：长度与成本

同一段 1000 字文本，分别截成 1/4、1/2、全文喂给模型，记录 `usage.prompt_tokens` 和耗时。画出趋势——你会亲眼看到平方级增长。

## 自测三问

1. Q 和 K 点积大，代表什么？为什么最后要乘 V 而不是乘 K？
2. 为什么"注意力是全连接的"，反而让模型难以精确计数和排序？
3. 因果掩码如果去掉，训练目标会变成什么？为什么不能用来生成？
