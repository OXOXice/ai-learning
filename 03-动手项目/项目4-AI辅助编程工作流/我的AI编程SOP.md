# 我的 AI 编程 SOP

> 用法：每次开新任务，照着从上到下走。哪一步跳过了、出了什么问题，写在最后一栏。

## 0. 开工前（3 分钟）

- [ ] 一句话说清：输入是什么、输出是什么、怎么算成功
- [ ] 列出 3 个边界情况（空文件？超大文件？权限不足？）
- [ ] 选模型：简单脚本用便宜模型，复杂逻辑用强模型

## 1. 让它先出方案（不写代码）

```text
我要做一个 {{功能}}。先不要写代码。
给出：文件结构、每个文件的职责、关键函数的签名、可能的坑。
用 200 字以内说明你的方案。
```

**通过标准**：方案里没有我不懂的词；我认可它的拆分。

## 2. 逐个文件生成

```text
按上面的方案，只写 {{文件}}。
要求：完整可运行、有错误处理、不要省略成 ...。
写完后列出你做的 3 个假设。
```

> "列出假设"这一句最值钱——它会把 AI 偷懒的地方暴露出来。

## 3. 验证（不可跳过）

- [ ] 跑通正常路径
- [ ] 跑 3 个异常输入
- [ ] 读一遍 diff，每行都问"这行为什么在这"
- [ ] 检查：有没有覆盖原文件、有没有硬编码路径、有没有吞异常

## 4. 记录

| 项目 | 提示词是否有效 | AI 写错的地方 | 怎么发现的 |
|---|---|---|---|
| 批量重命名 | 分层生成有效 | 没处理重名 | 造了同名文件测试 |
|  |  |  |  |

## 5. 沉淀

- 有效的提示词 → 存进 `02-提示词/我的提示词库.md`
- 踩过的坑 → 本文件末尾加一条
