# 项目 4 · AI 辅助编程工作流

**目标**：不是"让 AI 写点代码"，而是建立一套**稳定可控**的流程——你知道什么时候它可靠、哪里必须自己验。

## 任务

用 AI 从零写一个小工具（建议：批量重命名文件，或把 Markdown 转成 Excel），全程记录：
- 你给了什么提示词
- 它哪里写错了
- 你怎么发现错的（跑？看 diff？测边界？）
- 修正用了几个来回

## 流程框架（五步）

| 步 | 做什么 | 关键 |
|---|---|---|
| 1 定义 | 写清输入输出、边界、验收标准 | 一句话说不清就别开工 |
| 2 拆解 | 让 AI 先给方案和文件结构，**不要直接写代码** | 方案错了，代码全废 |
| 3 生成 | 一次只让它写一个文件/一个函数 | 大块生成必然夹带错误 |
| 4 验证 | 跑起来 + 造 3 个异常输入 + 读 diff | 不能跑的代码等于没写 |
| 5 固化 | 把有效的提示词存进 `02-提示词/我的提示词库.md` | 下次直接用 |

## 三个"AI 最容易骗你"的地方

1. **看起来能跑**：没报错但逻辑错（比如重命名覆盖了文件）
2. **异常路径不处理**：正常输入完美，文件不存在就崩
3. **编造 API**：库的用法是"最像话"的版本，不是真实签名

对应验证手段：造异常输入、加断言、查官方文档。

## 验收标准

- [ ] 工具能跑，且处理了至少 3 种异常输入
- [ ] `我的AI编程SOP.md` 写完，里面有具体的成功/失败案例
- [ ] 记录了 5 条"AI 写错但我一眼看穿"的例子
