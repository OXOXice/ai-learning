# 03 · 结构化输出与工具调用

## 一句话总结

想让模型稳定输出机器能读的东西，靠三件事：**明确 schema + 给示例 + 服务端约束（或解析重试）**。光写"请输出 JSON"是不够的。

## 1. 为什么"请输出 JSON"经常失败

模型的输出是自由文本，它可能：
- 包一层 ```json 代码块
- 前面加一句"好的，以下是结果："
- 字段名写成中文、少个引号、多个逗号
- 输出半截就被 `max_tokens` 截断

## 2. 三层保障

### 第一层：提示词

```text
只输出一个 JSON 对象，不要代码块标记，不要解释。
字段：
- title: string，不超过 20 字
- tags: string 数组，2–5 个，每个不超过 6 字
- score: 整数 0–10

示例：
{"title": "季度复盘", "tags": ["复盘", "目标"], "score": 7}
```

### 第二层：服务端能力

- **JSON mode**：`response_format={"type": "json_object"}`，服务端保证是合法 JSON
- **Structured Outputs / JSON Schema**：直接给 schema，服务端约束解码，字段和类型都对
- **工具调用（function calling）**：把"想让它输出的东西"定义成一个工具的**参数**，模型必须按 schema 填

> 经验：能用 JSON Schema 就别用"请输出 JSON"。

### 第三层：代码兜底

```python
import json

def parse_or_repair(text: str) -> dict:
    try:
        return json.loads(text)
    except json.JSONDecodeError:
        # 1) 去掉代码块标记
        cleaned = text.strip().removeprefix("```json").removeprefix("```").removesuffix("```").strip()
        try:
            return json.loads(cleaned)
        except json.JSONDecodeError:
            # 2) 交给模型修（附上错误信息）
            return repair_with_model(text)
```

**永远不要假设第一次就合法。**

## 3. 工具调用：把结构化输出用在行动上

工具声明示例：

```json
{
  "name": "search_orders",
  "description": "按用户手机号和日期范围查询订单，仅支持最近 90 天",
  "parameters": {
    "type": "object",
    "properties": {
      "phone": {"type": "string", "description": "11 位手机号"},
      "start": {"type": "string", "description": "YYYY-MM-DD"},
      "end": {"type": "string", "description": "YYYY-MM-DD"}
    },
    "required": ["phone", "start", "end"]
  }
}
```

写工具描述的三条经验：

1. **说清边界**（"仅支持最近 90 天"）比说清功能更重要
2. 参数给**格式示例**（`YYYY-MM-DD`），模型会照做
3. `description` 里写**什么时候该用**，不只写它是什么

## 4. 错误回传

工具执行失败时，不要抛异常结束，要把错误**结构化地回给模型**：

```python
{"ok": false, "error": "phone 参数格式错误，需要 11 位数字，收到 '138-0000'"}
```

模型看到具体错误，下一轮往往能自己改对。这是 Agent 能"自我修复"的关键机制。

## 5. 长度控制

结构化输出容易越写越长。两个手段：
- `max_tokens` 卡住
- schema 里给字段加长度约束（"title 不超过 20 字"）
