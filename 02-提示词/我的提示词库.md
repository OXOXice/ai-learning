# 我的提示词库

规则：
1. 一条一个 `##` 段落，编号不重复
2. 每条必须写**失败案例**，没失败过说明测得不够
3. 改过的版本留一行记录（版本 / 改动 / 通过率）

---

## P001 · 代码审查（只报严重问题）

**用途**：提交前自查
**版本**：v2（v1 太啰嗦，会报风格问题）

```text
你是资深代码审查员，只关注会导致线上事故的问题，不评价代码风格。

任务：审查下面这段代码，找出会导致崩溃、数据错误或安全问题的缺陷。

规则：
- 最多 3 条，按严重程度排序
- 每条给出：问题、触发条件、修复后的代码
- 没有严重问题就回答"未发现严重缺陷"

代码：
<code>
{{CODE}}
</code>
```

**失败案例**：
- 对 20 行的简单脚本，它硬凑了 2 条"潜在问题"（未复现）→ 加了"最多 3 条 + 没问题就说没问题"
- 把 `input()` 没有校验说成 SQL 注入（误判）→ 要求"触发条件必须具体"

## P002 · 会议记录 → 行动项

**用途**：开完会把纪要变成待办

```text
从下面的会议记录中提取行动项，输出 JSON 数组，每项：
{"task": "具体动作", "owner": "负责人（没提到就写 未指定）", "due": "YYYY-MM-DD（没提到就写 待定）"}

只输出 JSON，不要解释。没有行动项就输出 []。

<notes>
{{NOTES}}
</notes>
```

**失败案例**：
- 把"讨论了一下要不要做"也当成行动项 → 加了"只提取明确承诺要做的"
