# AI 学习计划（8 周 · 双轨）

> 🤖 **AI 生成说明**：本仓库的路线图、讲义与示例代码由 AI 起草，经人工调整后作为个人学习记录。
> 内容可能存在错误或过时；涉及事实、论文与结论，请以原始论文和官方文档为准。

> 用 1–2 个月，把「AI 为什么能用」和「我怎么用 AI 做出东西」两条线一起走完。
> 这个仓库是我的学习工作区：路线、讲义、代码、笔记都在这里。

## 我想拿到的三个结果

1. **能讲清楚**：不看稿子，用自己的话解释大模型是怎么"想"出一个字的，为什么它会一本正经地胡说。
2. **能写稳**：同一件事换不同问法，输出质量可控；有一份自己维护的提示词库，每条都经过测试。
3. **能做出来**：3–5 个能跑的小程序，从命令行聊天、文档问答，到一个会调用工具的 Agent。

## 双轨结构

| 轨道 | 目录 | 作用 | 每天 |
|---|---|---|---|
| 原理轨 | `01-原理/` | 搞懂机制：token、注意力、训练、采样、Agent 循环 | 约 40 分钟 |
| 动手轨 | `03-动手项目/` | 做出东西：写好提示词、写代码、调工具 | 约 60 分钟 |
| 横切 | `02-提示词/` | 两个轨道共用的手艺 | 穿插 |

两条轨**每周同一个主题**：原理给你判断力，动手暴露你理解的漏洞。第 3 天读不懂的概念，第 5 天在项目里撞上，就懂了。

## 8 周安排

| 周 | 原理轨（读 + 实验） | 动手轨（写 + 跑） | 周末交付 |
|---|---|---|---|
| 1 | 大模型到底是什么：预测下一个 token | 环境搭好，命令行聊天机器人 v1 | 能跑通的 `chat.py` |
| 2 | Token、向量、注意力机制 | 聊天 v2：多轮、流式、参数可调 | 一个自己会天天用的 CLI |
| 3 | Transformer 全貌 + 训练三阶段 | 提示词库：结构、模式、结构化输出 | 10 条经过测试的提示词 |
| 4 | 推理参数、成本、幻觉与边界 | 文档问答（RAG） | 能回答自己资料的问答器 |
| 5 | Agent 原理：工具调用与循环 | Agent v1：三个工具 | 会算数、查时间、读文件的 Agent |
| 6 | 记忆、规划、多步任务 | Agent v2：加记忆、重试、失败兜底 | 能完成多步任务的 Agent |
| 7 | 评测、安全与踩坑 | AI 编程工作流：让 AI 写一个完整项目 | 一套自己的结对编程流程 |
| 8 | 复盘：能力边界地图 | 每日简报 Agent 上线（定时跑） | 定时机器人 + 总复盘 |

里程碑：**M1 = 第 4 周末**（讲得清原理 + 2 个程序 + 提示词库）；**M2 = 第 8 周末**（3–5 个项目 + 一篇总结）。
每天的详细任务见 [ROADMAP.md](ROADMAP.md)。

## 每天 90 分钟的用法

- **0–15 分**：翻昨天的笔记，用一句话复述昨天学了什么（写不出来就是没学懂）。
- **15–55 分**：读当天讲义，做里面的"动手实验"——每个概念都必须亲手跑一次。
- **55–85 分**：推进动手项目，哪怕只加 10 行。
- **85–90 分**：在 `05-笔记/` 记三行：今天懂了什么、卡在哪、明天先干什么。

## 完成标准（不是"看完"，是"做出来"）

- [ ] 能不查资料画出「一句话 → token → 向量 → 注意力 → 下一个 token → 采样」这条链
- [ ] 能解释 temperature 和 top_p 的区别，并说清什么场景该调
- [ ] 提示词库里每条都有：用途、模板、测试过的输入、已知失败情况
- [ ] 5 个项目里至少 3 个能给别人用，有 README
- [ ] 写过一篇"AI 哪里靠不住"的总结，举自己踩过的 3 个例子

## 三条原则

1. **先跑通，再深究**。跑不通的原理先记成问题，不要卡死。
2. **每个概念配一个能复现的实验**。看懂了不算，跑出来才算。
3. **笔记用自己的话**。复制粘贴的笔记等于没记。
